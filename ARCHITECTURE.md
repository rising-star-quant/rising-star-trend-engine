#### **Sprint 1: DataConnector & Infrastructure Setup**

* **Status:** `IN PROGRESS`
* **Description & Scope:**
* Define shared Pydantic data schemas (`MarketDataPayload`).
* Implement the `DataConnector` micro-module using `yfinance` / external APIs with exponential backoff for rate limits.
* Set up initial local DB/cache schemas (PostgreSQL & Redis configuration).
* Build a comprehensive `pytest` test suite with mocked financial payload responses.


* **Definition of Done (DoD):** A working data pipeline that ingests, normalizes, and passes market data payload objects cleanly with full unit test coverage.

#### **Sprint 2: RuleEngine (Fundamental Eligibility Filters)**

* **Status:** `NEW`
* **Description & Scope:**
* Implement static eligibility checks (U.S. incorporation, S&P 500 market cap thresholds, liquidity, public float).
* Implement financial health criteria (positive GAAP Net Income over the last 4 quarters combined and positive in the most recent quarter).
* Connect `RuleEngine` to input payloads generated by `DataConnector`.
* Write `pytest` unit tests for both passing and failing stock universe edge cases.


* **Definition of Done (DoD):** A stateless pure function module that outputs a verified, documented `EligibleUniverse` list.

---

#### **Sprint 3: IndicatorEngine & ScoringEngine**

* **Status:** `NEW`
* **Description & Scope:**
* Build `IndicatorEngine` using Pandas / TA-Lib to compute $MA_{50}$, $MA_{200}$, moving average slopes, and Accumulation Days volume ratios.
* Implement 20-day resistance breakout triggers.
* Implement `ScoringEngine` to aggregate multi-factor weights (Technical 40%, Volume 30%, Sector 20%, Short Interest 10%) into a normalized 0–100 *Rising Star Score*.
* Write unit test suites covering indicator calculations and scoring edge cases.


* **Definition of Done (DoD):** Engine produces real-time ranks and active breakout flags for eligible candidates.

---

#### **Sprint 4: RiskGuard & NotificationHub**

* **Status:** `NEW`
* **Description & Scope:**
* Build `RiskGuard` module to monitor trailing stop-losses, $MA_{50}$ breakdowns, and maximum time exit rules (60-day holding limit).
* Build `NotificationHub` module using `httpx` to format and dispatch alert cards to a Telegram Bot / Webhooks.
* Implement Redis-based deduplication (idempotency checks) to prevent duplicate alerts.
* Write unit tests for alert formatting and risk trigger logic.


* **Definition of Done (DoD):** Real-time Telegram alert delivery upon trade signal generation, with active position risk monitoring.
